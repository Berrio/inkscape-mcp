# F02 — Workspace, XML y transacciones

## F02-WP01 (en curso)

- ADR-008 define cliente/documento hostil, ACL requeridas en los roots y el límite TOCTOU de Node sin helper privilegiado.
- `WorkspaceService` crea IDs opacos de roots canónicos y resuelve solo paths relativos seguros.
- Las entradas existentes usan `realpath`; los outputs nuevos validan el parent canónico. Se rechazan absolute, UNC, drive-relative, NUL, ADS y segmentos de traversal.
- La prueba Windows usa una junction de directorio para demostrar que un escape a otro root se rechaza sin requerir el privilegio de crear symlinks de archivo.

## F02-WP02 (en curso)

- `ScratchManager` crea dirs únicos de job/probe/staging, garantiza limpieza `finally` y recolecta solo dirs propios obsoletos durante arranque.
- `sha256File` calcula revisiones por stream; una mutación interna porta `MutationDocumentRef` y el overwrite exige la revisión actual del destino.
- Locks por rutas canónicas se adquieren en orden léxico, evitando deadlocks entre source y output.
- `AtomicFileStore` escribe y sincroniza un temporal en el mismo directorio, crea backup único al reemplazar y después hace rename; ADR-005 declara los límites crash/Windows de esta operación.
- Las pruebas cubren revisión obsoleta, overwrite sin revisión, backup y dos writers concurrentes.
- `SnapshotStore` copia documentos a IDs opacos con owner, TTL/retención y restauración mediante la misma comprobación de revisión; los handlers MCP llegarán al registrar el catálogo de workspace/documentos.
