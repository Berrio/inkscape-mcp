# F12 — Opcionales posteriores a 1.0

Registro de evidencias. Ninguna opción de F12 se publica en el catálogo MCP de 1.0. Cada tarea cerrada aporta una medición, una evaluación o un diseño con su ADR.

## F12-WP01/WP02 (2026-10-07)

- **F12-T01 — benchmark de `inkscape --shell`.**
  - `scripts/bench-f12-shell.mjs` (`npm run bench:f12-shell`) compara exportaciones PNG en procesos batch con una sesión `--shell` persistente.
  - La sesión hace reset por documento (`file-open … export-do; file-close`) y se mide:
    - working set del árbol, para el memory cap;
    - validez de cada PNG;
    - recuperación tras matar la sesión.
  - Resultados (Windows 11, Inkscape 1.4.4 MSIX, 30 exportaciones):
    - batch: 1.598 ms de media por exportación;
    - `--shell`: 11 ms de media, con arranque de 1,3–2,3 s;
    - memoria de la sesión: +6,4 MiB;
    - recuperación tras crash: ~2 s.
  - Un worker aislado necesitaría un modo de runner con stdin interactivo, inexistente por diseño; la medición se hace con el benchmark aislado, no desde el producto.
- **F12-T02 — decisión.** ADR-013: no se adopta el shell persistente en el núcleo, por cinco motivos:
  - no hay resultado por comando;
  - las rutas se pueden inyectar en la cadena de acciones;
  - hay estado compartido entre owners;
  - no es compatible con el runner/Job Object actual;
  - la fiabilidad ya probada está en el modelo batch.

  Quedan fijadas las condiciones para un futuro worker opt-in sólo para previews.

- **F12-T03/T04/T05 — puente GUI.** ADR-014 diseña:
  - la extensión compañera, con catálogo cerrado y operación sobre el documento abierto;
  - el handshake: named pipe con ACL, token de un solo uso y protocolo `inkscape-mcp-gui/1` con política de versión;
  - el modelo de permisos separados.

  El puente está deshabilitado: `configInputSchema` es estricto y no tiene ninguna opción GUI, y no existe tool ni proceso.

- **F12-T06 — sandbox de SO.** ADR-015 evalúa las opciones en este host:
  - AppContainer: recomendado si se aborda;
  - Windows Sandbox: no habilitado;
  - Docker 29.6.1 con contenedores Linux: aislamiento útil, pero es otra plataforma;
  - WSL: sin aislamiento real.

  1.0 mantiene `nativeParserIsolation: none` y `trusted-local-only`.

- **F12-T07 — sigue `[~]`.** Requiere un especialista de preprensa y fixtures PDF/X reales; no se puede cerrar con evidencia local.
- **F12-T08 — adaptadores externos.** Scour, SVGO, resvg, rsvg-convert, CairoSVG e ImageMagick no están en `PATH`. ADR-016 fija las reglas:
  - no sustituir a Inkscape en silencio;
  - descubrimiento sólo por arranque;
  - probe real;
  - regresión visual obligatoria;
  - mismo runner.
- **F12-T09 — plugins.** ADR-016 diseña una API de plugins compilados y registrados de forma estática, habilitados por allowlist de arranque y sin carga dinámica desde el cliente.
- **F12-T10 — helper basado en handles.** Prueba de viabilidad con `koffi`:
  - `FILE_FLAG_OPEN_REPARSE_POINT` detecta una junction;
  - `GetFinalPathNameByHandleW` revela su destino fuera del workspace.

  ADR-017 describe el resolver con `NtCreateFile` relativo a handles. No se implementa mientras el modelo de amenaza exija roots privados.

- **F12-G01.** Ningún opcional de F12 se publica en 1.0. Todos los evaluados tienen ADR con threat model y condiciones de publicación: capability gate, tests y documentación.

Verificación: `npm run check` y `npm run bench:f12-shell -- --exports 30` en verde.
