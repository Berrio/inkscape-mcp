# F01 — Configuración, doctor, discovery y runner

## F01-WP01

- Objetivo verificable: disponer de configuración segura, determinista y redactable antes de abrir workspaces o iniciar procesos.
- Prerrequisitos/puertas: F00 cerrado.
- Interfaces disponibles: `loadConfig`, `loadConfigFromCli`, `parseConfigFlags`, `assertDocumentWorkspace` y `redactConfig`.
- Archivos/artefactos esperados: schema Zod, loader JSON/env/flags, configuración redactada, documentación y fixtures de config.
- No-objetivos: ejecutar Inkscape, arrancar un servidor MCP o acceder a documentos.

### Decisiones y contratos

- Precedencia: flags > entorno allowlisted > JSON > defaults.
- `workspaceRoots` se expresa en config administrativa. Las tools no recibirán rutas absolutas.
- `doctor` puede cargar config sin roots y reportar `workspaceReady: false`; `assertDocumentWorkspace` impide el uso posterior de document tools sin root.
- HTTP está restringido a `127.0.0.1` y auth `required`, aun cuando no se implemente el handler hasta F10.
- Paths de workspaces, scratch y ejecutable se sustituyen por estados `configured` en logs/resultados.

### Verificación ejecutada

- 11 pruebas correctas: defaults, precedence, roots ausentes, invalidación Zod, límites, flags allowlisted, JSON válido/malformado/desconocido, HTTP local y redacción.
- Formato, lint, TypeScript estricto y build correctos.
