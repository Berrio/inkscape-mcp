# F10 - Transporte HTTP experimental

## WP01 (2026-08-27)

- El transporte HTTP es opt-in y sigue siendo P2: `stdio` permanece como
  predeterminado y no cambia su framing de stdout.
- `src/http.ts` adapta `node:http` al handler oficial `createMcpHandler` v2,
  usando una factoría por request, sólo el endpoint `/mcp` y tráfico moderno
  stateless. El runtime de proceso preserva jobs, artifacts, planes, cachés y
  locks entre requests, sin convertir la instancia MCP en una sesión. El
  protocolo legacy se rechaza deliberadamente en esta superficie.
- El proceso sólo escucha `127.0.0.1`; valida Host y Origin mediante helpers
  oficiales del SDK antes de autenticar o despachar. Los requests tienen límite
  de cuerpo `maxInputBytes`, timeout del proceso y 120 solicitudes/minuto.
- El bearer token obligatorio procede únicamente de
  `INKSCAPE_MCP_HTTP_TOKEN`, es base64url de al menos 32 caracteres y se compara
  en tiempo constante. No entra en config, argumentos, logs ni respuestas; la
  rotación actual es por sustitución de variable y reinicio.
- El stderr HTTP usa JSON estructurado mínimo para arranque, rechazo y errores
  de servidor; sólo publica evento y status, nunca headers, token, URL, cuerpo
  ni rutas documentales.
- Evidencia: `tests/unit/http.test.ts` cubre token ausente/inválido, Host y
  Origin adversarios, endpoint, rate limit y listener real efímero que rechaza
  un POST sin bearer. También conecta `StreamableHTTPClientTransport` v2 con
  bearer, negocia `2026-07-28` y lista herramientas end-to-end. `npm run check`
  pasa con 222 pruebas y una omitida.

Pendiente: ownership por principal, logger/telemetría, Inspector/conformance
HTTP y una revisión formal del threat model antes de cualquier anuncio estable.

## F10-WP01 — auth, ownership y observabilidad (2026-08-31)

- `F10-T04` queda cerrada: HTTP acepta el token único de entorno o el proveedor
  interno `INKSCAPE_MCP_HTTP_TOKENS_FILE`. Este último lee un JSON estricto de
  principals/tokens en cada request; reemplazarlo atómicamente rota credenciales
  sin reiniciar. Si no puede leerlo o validarlo, el endpoint falla cerrado con
  `503`; los valores no entran a stdout, resultados ni eventos.
- `F10-T05` queda cerrada: la factoría HTTP oficial recibe `authInfo` y genera
  un owner efectivo derivado por hash de principal+workspace. Artifacts,
  snapshots, planes, jobs, recursos de documento y manifests no se comparten
  entre principals. Las URI de recursos se validan contra el principal, además
  de seguir siendo opacas; stdio conserva sus owners por workspace.
- `F10-T06` queda cerrada: `@opentelemetry/api` 1.9.1 y
  `@opentelemetry/sdk-trace-base` 2.10.0 producen una traza por request a través
  de un exportador allowlisted. stderr recibe sólo evento, status, duración y
  correlación hash de principal, nunca URL, header, token, body, ruta o SVG.
  `docs/http-security.md` registra el threat model, rotación y límites.
- `F10-T07` queda `[-]` con evidencia, no como éxito: Inspector 2.3.0 y
  Conformance 0.1.16 del lockfile sólo ofrecen `2025-11-25`. La sonda
  `npm run test:f10-inspector` arranca el endpoint protegido, comprueba que el
  Inspector recibe el rechazo moderno esperado y que Conformance no enumera
  `2026-07-28`; fallará si esos resultados cambian para obligar a crear la
  conformance real. Ninguna capability HTTP se anuncia estable por este hecho.
- Verificación: `npm run check` (79 archivos correctos, 316 pruebas correctas
  y 1 omitida) y `npm run test:f10-inspector` el 2026-08-31.
- Archivos: `src/http.ts`, `src/http-telemetry.ts`,
  `src/server/ownership.ts`, stores de resources/artifacts, CLI, pruebas HTTP y
  ownership, la sonda fijada, documentación de seguridad, dependencias y este
  registro.

## F10-WP02 — baseline 1.4.4 y gate de páginas 1.5 (2026-08-31)

- Se añadió una política de versión: el único soporte estable es Windows con
  Inkscape 1.4.4 y adapter `pages_v14`. El resultado aparece sin rutas
  privadas en `doctor` y `inkscape_status`; los otros parches 1.4, 1.5+ y
  plataformas no verificadas no heredan esa etiqueta.
- Capabilities conserva la versión dentro de su huella y detecta deriva:
  valida los flags base de exportación y que `--action-list` esté disponible
  y no vacío. Las diferencias se devuelven como warnings accionables.
- El adapter DOM de F03 mantiene `inkscape:page` y ahora rechaza
  `svg:view` antes de listar, añadir, actualizar, borrar o reordenar. Así no
  se pierde una representación futura mientras `pages_v15` siga ausente.
- `pages_v15` y los fixtures 1.4.4/1.5 quedan `[-]`: esta máquina sólo
  tiene el baseline 1.4.4 y el plan exige una release 1.5 real, no una
  simulación. La política anuncia el estado experimental y no publica esa
  capability.
- Evidencia: `node dist/cli.js --doctor --json` observó MSIX 1.4.4, 189
  acciones, todos los flags base y cero warnings; pruebas focalizadas
  (51/51), `npm run test:f03-g09`, `npm run test:mcp` y `npm run check`
  (79 archivos correctos, 319 pruebas correctas y 1 omitida).
- Archivos: política discovery, capabilities, adapter de páginas, doctor,
  schema/status MCP, smoke MCP, matriz de compatibilidad, pruebas unitarias y
  este registro.
