# F08 — Importación, formatos adicionales, presets y paquetes

## F08-WP06 (descubrimiento INX, continuación 2026-08-29)

- El inventario interno lee manifests INX exclusivamente de directorios
  controlados por Inkscape/perfil, limita archivos y tamaño, y descarta DTD o
  entidades XML. El doctor publica sólo el conteo, no rutas ni IDs aceptables.
- En la instalación Windows de referencia se detectaron 17 exportadores INX
  estructuralmente válidos. Ninguno se anuncia todavía: falta fixture y smoke
  headless específico por adapter.
- Evidencia: prueba unitaria positiva y de XML hostil; `npm run check` pasó con
  271 pruebas y una omitida.

## F08-WP06 (adapter DXF, continuación 2026-08-29)

- La sonda real DXF se corrigió para aceptar la forma válida con comentario
  inicial `999`; ahora valida pares estructurales `SECTION`/`EOF` y rechaza
  bytes binarios antes de anunciar la capability.
- `document_export` publica únicamente el adapter versionado
  `inkscape-dxf/v1`. Su schema cerrado permite sólo `format: "dxf"`, área
  drawing/selection y el acknowledgement literal
  `fidelityPolicy: "acknowledge-limited-fidelity"`; no acepta IDs de
  extensiones, opciones ni argv aportados por el cliente.
- La exportación conserva bundle nativo, staging, revisión esperada, commit
  atómico y publicación de artifact. Verifica DXF ASCII antes de publicar y
  devuelve `DXF_LIMITED_FIDELITY_ACKNOWLEDGED`; la fidelidad de estilos SVG
  complejos no se promete.
- Se añadió cobertura unitaria para estructura DXF y schema, y el smoke MCP
  exporta un DXF real con Inkscape 1.4.4. Documentación de herramientas y
  matriz de compatibilidad actualizadas.
- Evidencia: `npm run test:mcp` contra Inkscape 1.4.4 y `npm run check`
  pasaron; este último ejecutó 275 pruebas, una omitida.

## F08-WP06 (adapter HPGL, continuación 2026-08-29)

- La sonda controlada de la extensión HPGL instalada produjo un flujo ASCII
  con inicialización `IN;` y comandos de pluma. El verificador rechaza salida
  binaria, no inicializada o sin movimientos de pluma antes de publicar.
- `document_export` añade exclusivamente `inkscape-hpgl/v1`, con el mismo
  schema cerrado, staging, revisiones, commit atómico y artifact que DXF. No
  admite perfil de plotter, ID de extensión ni parámetros de hardware del
  cliente; exige acknowledgement de fidelidad limitada y devuelve warning.
- El smoke MCP exporta HPGL real con Inkscape 1.4.4. PLT y G-code permanecen
  no anunciados: no comparten todavía un contrato seguro, fixtures y
  verificador de interoperabilidad.

## F08-WP06 (evaluación de G-code y WebP, continuación 2026-08-29)

- `Path to Gcode` no declara `<output>`: es un efecto que solicita directorio,
  nombre de archivo y postprocesador personalizable. No se expone una tool ni
  se intenta convertir esas entradas peligrosas en argv; permanece bloqueado.
- La extensión WebP está instalada, pero su sonda SVG→WebP controlada terminó
  sin artefacto. El doctor informa capability ausente y una razón estable, sin
  filtrar la ruta de scratch; la prueba unitaria comprueba esa no filtración.
- JPG, TIFF y PLT permanecen fuera del catálogo hasta contar con una sonda
  headless, verificador estructural y adapter con schema fijo por formato.

## F08-WP06 (cierre de F08-T32, continuación 2026-08-30)

- Las sondas fijas de JPEG y TIFF se suman a WebP: las tres extensiones están
  instaladas pero terminan sin output verificable. El doctor devuelve estados
  de capability ausente y razones estables, sin rutas de scratch.
- No hay manifiesto de exportación PLT; HPGL es el único formato de plotter
  declarado y ya tiene adapter propio. Con DXF/HPGL disponibles y G-code/raster

## F08-WP06 (hardening de lectura INX, continuación 2026-08-30)

- El inventario ya no carga cada manifest completo antes de verificar su límite:
  lee como máximo 512 KiB más un byte sentinela y procesa los archivos de forma
  secuencial. Así, hasta 512 INX instalados no multiplican el presupuesto de
  memoria por lecturas paralelas.
- Un INX ilegible, mayor que el límite, malformado o con ID fuera del alfabeto
  permitido se descarta sin abortar el descubrimiento de los demás. Las pruebas
  cubren esos negativos junto con el manifest válido.
- F08-T31 continúa parcial: la CLI no selecciona de manera segura un manifest
  concreto cuando varias extensiones comparten el mismo tipo de salida; no se
  anuncian esos formatos ni se aceptan IDs de extensión como alternativa.

## F08-WP06 (evaluación de GPL, continuación 2026-08-30)

- Se añadió un verificador estructural de GIMP Palette: exige firma, nombre,
  columnas acotadas y al menos un color RGB válido, además de una sonda fija
  que no acepta ID ni opciones de extensión.
- La sonda real contra Inkscape 1.4.4 termina sin `.gpl` verificable. El doctor
  devuelve una capability ausente con razón estable, sin ruta de scratch, y
  GPL permanece fuera de `document_export` y del catálogo público.
- La prueba de lectura INX cubre también los IDs legítimos con `_`; esto
  conserva los 17 manifests instalados en el inventario tras el hardening.

## F08-WP06 (adapter FXG, continuación 2026-08-30)

- La sonda fija FXG produjo XML válido en Inkscape 1.4.4. El verificador exige
  XML no activo, raíz `Graphic`, versión 1.0/2.0 y contenido dibujable; una
  salida vacía, binaria o malformada no se publica.
- `document_export` anuncia exclusivamente `inkscape-fxg/v1`, con formato,
  área y acknowledgement de fidelidad literal. Conserva NativeInputBundle,
  staging, revisión, commit atómico y artifact; no recibe IDs ni opciones de
  extensión. El smoke MCP exporta y verifica un `.fxg` real.
- FXG es experimental: su conversión XSLT no promete fidelidad de SVG complejo
  ni compatibilidad con herramientas Adobe/Flash actuales.

## F08-WP06 (document_optimize, continuación 2026-08-30)

- `document_optimize` ofrece un plan `dryRun` por defecto y sólo considera la
  eliminación conservadora de defs top-level sin referencias. La salida por
  defecto es un SVG hermano `*.optimized.svg`; el documento fuente no se
  reescribe.
- La publicación exige `expectedRevision`, NativeInputBundle, staging y commit
  atómico. Antes del commit Inkscape renderiza source y candidato a PNG y el
  comparador exige cero píxeles distintos (tolerancia limitada y explícita).
- El smoke MCP cubre plan derivado, rechazo sin revisión y SVG publicado sin
  la def no usada, con regresión visual cero. Evidencia adicional: `npm run
check` pasó con 277 pruebas y una omitida antes del smoke final.

## F08-WP01 (en curso)

- `document_import_svg` incorpora un SVG existente del workspace a un output
  nuevo, con revisión esperada y commit atómico.
- El importador llama al sanitizador antes de publicar y respeta el máximo de
  política configurado; por tanto no permite elevar preserve-local a trusted.
- La integración MCP crea un SVG con `<script>` y `onclick`, aporta el SHA-256
  crudo del archivo (un documento hostil no tiene que ser inspeccionable para
  importarse) y comprueba que el SVG destino conserva el rectángulo permitido
  pero no el script ni el event handler.
- `assets_package` publica `document.svg`, las dependencias locales reescritas
  bajo `assets/`, y `manifest.json` con revisiones SHA-256. Reutiliza la
  cuarentena de entrada nativa: no sigue rutas absolutas, externas ni fuera del
  workspace, limita cada recurso y comprueba revisiones antes de publicar.
- Toda dependencia requiere una declaración de licencia explícita y exacta por
  `sourceUri`; las licencias duplicadas, sobrantes o ausentes se rechazan antes
  de escribir archivos. Esto evita empaquetar fuentes o recursos de licencia
  incierta por accidente.
- La prueba MCP comprueba los bytes copiados, URI reescrito y manifiesto de un
  paquete con una dependencia local; también abre `document.svg` empaquetado y
  lo renderiza con Inkscape real. SVGZ, raster, PDF, fuentes y perfiles siguen
  pendientes como adaptadores de importación.

## F08-WP01 (completado el 2026-08-29)

- `publishImportedSvg` concentra la publicación de todo importador como una
  única transacción de SVG saneado/wrapper más manifest reproducible. SVG/SVGZ,
  raster y PDF ya comparten la misma salida atómica, sus revisiones y la
  comprobación de que el sidecar existe.
- El importador PDF deja de entregar el archivo del workspace directamente a
  Inkscape: copia `input.pdf` al staging controlado y compara su SHA-256 con
  `expectedRevision` antes de arrancar y antes de publicar. La salida nativa se
  vuelve a sanear antes de entrar al pipeline común.
- La capability runtime de `--list-input-types` gobierna el importador PDF y
  `--help-all` gobierna sus flags. Raster sigue siendo un adaptador interno por
  firma y dimensiones; no convierte una capability externa en una superficie
  pública nueva.
- Evidencia: pruebas focalizadas de SVG/raster/PDF/storage, `npm run test:mcp`
  con los tres importadores reales y posteriormente `npm run check`.

## F08-WP02 (2026-08-27)

- `document_import` añade importación de SVG y SVGZ como documentos SVG nuevos
  y saneados. SVGZ exige cabecera gzip y se descomprime con `maxOutputLength`,
  por lo que un zip bomb no puede expandirse fuera del límite configurado.
- La publicación usa `commitBatch` para crear el SVG y un manifest sidecar
  `inkscape-mcp-document-import/v1`; éste registra formato, bytes, hashes y
  las pérdidas aplicadas por la sanitización, sin rutas absolutas.
- `document_import_capabilities` publica de forma acotada los tipos de entrada
  que devuelve la sonda local `--list-input-types`, para que los adaptadores
  nativos posteriores se activen por evidencia y no por una extensión asumida.
- `web-asset-pack` entrega SVG plano más PNG transparentes 1×/2×/3× y
  `print-pdf-300dpi` fija la rasterización de filtros a 300 dpi. Ambos se
  expanden al contrato normal de lotes, por lo que conservan staging,
  verificación y publicación consistente.
- `document_import_pdf` importa una página PDF a SVG usando el importador
  interno o Poppler, según capabilities reales. Valida firma/tamaño, limita la
  página, allowlistea las estrategias internas y publica SVG + manifest con
  pérdidas declaradas. El smoke MCP genera un PDF real y prueba ambos modos.
- Evidencia: `npm run check` completó 179 pruebas (una omitida) y `npm run
test:mcp` completó las comprobaciones MCP modernas y legacy por stdio,
  incluyendo el SVGZ saneado y su manifest.

## F08-WP02 (continuación 2026-08-29)

- `document_import_postscript` admite exclusivamente EPS y PostScript locales
  ya autorizados por el workspace. Exige extensión coherente, firma `%!`,
  `expectedRevision`, staging controlado, salida SVG saneada y publicación
  atómica con el manifest `inkscape-mcp-document-import/v1`. Declara siempre
  la pérdida `POSTSCRIPT_NATIVE_IMPORT_FIDELITY_NOT_GUARANTEED`.
- `document_import_capabilities` ejecuta un fixture EPS/PS fijo y efímero con
  el runner único. Sólo declara `validated`/`available` cuando hay SVG real;
  un error, timeout o salida ausente queda `not-headless` y bloqueado. AI,
  EMF, WMF, XAML y DXF permanecen detectados pero bloqueados sin adaptador.
- Se añadió el fixture first-party MIT `minimal.eps`, con manifest de fixture,
  smoke MCP de conversión/render y un negativo de EPS corrupto que comprueba
  que no aparezcan SVG ni manifest.
- Evidencia: `npm run build`, pruebas unitarias de fixture/gates y
  `npm run test:mcp` por stdio con Inkscape 1.4.4 finalizaron correctamente.
- F08-T09 sigue parcial: faltan política y fixtures para dependencias de
  fuentes/perfiles de importación.

## F08-WP02 (cierre 2026-08-29)

- PDF y EPS/PS aceptan `dependencyPolicy` estricto: por defecto `record`; de
  manera opt-in, `reject-missing` cancela antes de publicar cuando el SVG
  resultante declara una fuente concreta no instalada y `reject-unresolved`
  hace lo mismo ante nombres ICC sin perfil local. El manifest incluye el
  preflight de fuentes, inventario ICC y las limitaciones honestas de cobertura,
  embedding, conversión CMYK y output intents.
- Las pruebas unitarias ejercitan registro y rechazo independiente de fuentes y
  perfiles. El smoke MCP comprueba que los manifests reales de EPS y PDF
  contienen la política y las limitaciones de preflight, junto con los casos
  previos de archivo corrupto, cifrado, tamaño extremo y SVGZ.
- F08-T06 a T10 quedan cerradas. Evidencia de cierre: `npm run test:mcp` con
  Inkscape 1.4.4 y `npm run check` completó 262 pruebas (una omitida).

## F08-WP03 (2026-08-27)

- `document_export_preset_plan` expande y verifica un preset antes de publicar
  archivos; entrega un digest de la revisión fuente, preset y capabilities
  observadas, junto con un token de ejecución ligado al workspace.
- `document_export_batch` acepta exclusivamente `specs`, `preset` o
  `planToken`. Un plan se consume una sola vez y expira por defecto a los cinco
  minutos (máximo quince), evitando que un cliente repita una exportación
  preflighted por error.
- Evidencia: `npm run check` completó 181 pruebas (una omitida) y `npm run
test:mcp` superó los flujos modernos y legacy con Inkscape real; las pruebas
  unitarias cubren propiedad, consumo único y aislamiento entre workspaces.

## F08-WP03 (continuación 2026-08-29)

- `document_export` expone PS nivel 2/3 y EPS con schemas ya tipados, sin
  argv ni formatos libres. Ambos se renderizan desde un `NativeInputBundle`,
  se verifican por firma PostScript y, para EPS, por `BoundingBox` concreto
  antes del commit.
- El preflight de PostScript detecta filtros, máscaras y opacidad. La política
  por defecto `reject` evita una rasterización implícita; el cliente sólo puede
  usar `rasterize-with-warning` como aceptación explícita de la pérdida.
- El smoke MCP exporta PS y EPS reales, reimporta el EPS resultante a SVG y
  comprueba que la transparencia se rechaza sin publicar salida. EMF, WMF y
  XAML siguen bloqueados: aún no poseen verificador ni fixture de round-trip.

## F08-WP03 (EMF, continuación 2026-08-29)

- EMF se habilita con validación binaria de `ENHMETAHEADER`, preflight de
  flattening explícito y los mismos límites, staging, revisiones y manifests
  usados por los importadores nativos. No acepta formatos ni argumentos libres.
- La capability EMF no depende sólo de `--list-input-types`: ejecuta un fixture
  server-owned SVG→EMF→SVG y permanece `not-headless`/bloqueada si falla.
- El smoke MCP verifica exportación e importación EMF reales, incluido el
  round-trip a SVG. WMF y XAML continúan bloqueados por no tener verificadores
  estructurales ni fixtures aprobados.

## F08-WP03 (WMF, continuación 2026-08-29)

- WMF se ofrece sólo como exportación experimental. Valida la cabecera estándar
  o Placeable WMF, conserva el preflight de flattening y siempre añade
  `WMF_EXPERIMENTAL_COMPATIBILITY`; no promete interoperabilidad universal.
- El smoke MCP exporta WMF real y la prueba unitaria cubre su cabecera. La
  importación WMF y XAML continúan bloqueadas hasta disponer de round-trip y
  fixtures de consumidores aprobados.

## F08-WP03 (capabilities opcionales, continuación 2026-08-29)

- La sonda local confirma el tipo XAML de Inkscape, pero el host no tiene un
  runtime WPF que pueda cargar un documento XAML ni un consumidor Avalonia.
  Por tanto XAML queda deliberadamente fuera de `document_export`: no basta que
  Inkscape produzca XML para prometer interoperabilidad con sus consumidores.
- `scour` tampoco está instalado o detectable. El MCP no anuncia una
  optimización SVG ficticia ni reemplaza el adaptador opcional por cambios
  estructurales no equivalentes; SVG plano continúa soportado por su ruta
  propia.
- El doctor detecta JPEG y TIFF como **entradas** (cubiertas por el importador
  raster existente), pero la ayuda de salida no lista JPG, WebP ni TIFF y no se
  halló un exportador adicional validable. No se publica ninguna salida raster
  adicional.
- Evidencia local: sonda WPF/XAML falló de forma controlada, `Get-Command
scour` no encontró ejecutable y `--doctor --json` no anunció esos tipos como
  formatos de salida.

## F08-WP04 (presets y workflows, continuación 2026-08-29)

- Los presets de exportación declaran `inkscape-mcp-export-preset/v1`; las
  definiciones reutilizables se resuelven con
  `inkscape-mcp-export-preset-definition/v1`, sin padres desconocidos, IDs
  duplicados ni ciclos. Sus overrides son strict y limitados a texto o tamaño.
- `print-pdf-300dpi` acepta ahora `overrides.text` con `preserve` o `paths`.
  Los tres presets sociales publican PNG con tamaños definidos y permiten un
  override de ancho/alto sólo si ambos valores son explícitos.
- Un preset social exige fecha ISO y etiqueta de fuente. La metadata no altera
  el SVG: viaja ligada al plan de un uso y queda en el manifest publicado del
  lote atómico. El smoke MCP realizó el plan y la exportación social real.

## F08-WP04 (2026-08-27)

- `document_import_raster` incorpora BMP/TIFF/TGA no comprimidos, PNG, JPEG, GIF y WebP locales como SVG
  nuevo mediante un wrapper tipado de tamaño intrínseco. El formato se detecta
  exclusivamente por firma/estructura de bytes; la extensión puede ser falsa y
  nunca gobierna la decisión.
- La lectura limita bytes y megapíxeles antes de generar el SVG. El modo
  `embed` encapsula sólo el MIME permitido; `link` conserva una referencia
  relativa al asset ya autorizado dentro del workspace. Ambos publican SVG y
  manifest en un solo `commitBatch`, sin descargas ni rutas absolutas.
- El manifest declara dependencia en modo link, coste de tamaño en embed y las
  limitaciones de orientación EXIF JPEG o animación GIF. Las pruebas unitarias
  cubren cabeceras/dimensiones BMP/TIFF/TGA/PNG/JPEG/GIF/WebP y límite de megapíxeles; el
  smoke MCP cubre embed y link con una fuente PNG cuyo nombre usa extensión
  falsa, además de importar y renderizar fixtures BMP/TIFF/TGA no comprimidos.
- Evidencia: `npm run check` completó 188 pruebas (una omitida) y `npm run
test:mcp` completó los flujos MCP modernos y legacy por stdio con Inkscape
  real.

## F08-WP05 (2026-08-27)

- Las importaciones SVGZ ya limitaban la descompresión y los fixtures raster
  cubrían cabeceras truncadas o corruptas. `document_import_pdf` añade rechazo
  previo de PDFs que declaran `/Encrypt`, antes de abrir Inkscape y antes de
  publicar SVG o manifest; evita un diálogo de contraseña/headless ambiguo.
- El smoke MCP escribe un fixture PDF cifrado mínimo y comprueba `isError`, el
  diagnóstico recuperable y la ausencia de ambos outputs. La detección ignora
  comentarios, strings literales y cadenas hexadecimales; una coincidencia
  estructural se prefiere rechazarla a pasar un PDF potencialmente interactivo
  al proceso nativo.
- Aún faltan fixture y política explícitos para páginas PDF de dimensiones
  extremas y para dependencias de fuentes/perfiles; F08-T09 permanece parcial.
