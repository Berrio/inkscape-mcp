# F03 — Documentos, unidades, viewBox y páginas

## F03-WP01 (completo)

- ADR-010 fija 96 CSS px/in, separación de viewport físico y user units, y `preserve_user_scale` como política `page_only` por defecto.
- `geometry` modela longitudes físicas/CSS, páginas, rectángulos de usuario y matrices de resize explícitas.
- Los vectores normativos A4, contain y cover se prueban con tolerancias de punto flotante. El escalado DOM/CSS avanzado no se anuncia aún.
- `createSvgDocument` genera SVG con namespaces y `viewBox` coherente; `resizePageOnlySvg` actualiza página/viewBox sin transformar elementos.
- El catálogo MCP ya expone `workspace_list`, `workspace_list_documents` y `document_create` con schemas estrictos. `test:mcp` crea un A4 en un root temporal por stdio sin paths absolutos.
- `document_resize` implementa `page_only` con `expectedRevision`, backup, commit atómico y nueva revisión; la integración stdio confirma A4 → 148 × 210 mm sin modificar elementos.
- El primer pipeline `export_png` ya usa staging, runner seguro, opciones allowlisted, verificación PNG/IHDR y commit atómico. La integración local exportó 400 px con Inkscape MSIX 1.4.4; su contrato completo se ampliará en F05.
- `export_pdf` aplica el mismo pipeline y valida `%PDF-x.y`; la integración MCP real exportó PDF 1.5 con la instalación MSIX. El verificador ya lee page count y MediaBox; estrategia multipágina/subset y tolerancias siguen planificadas en F05.
- `export_svg` produce SVG Inkscape o plain SVG con verificación de XML/SVG seguro. El test MCP real cubre ahora PNG, PDF 1.5 y plain SVG desde el mismo A4.
- `document_inspect` devuelve viewport, `viewBox` y SHA-256 con control opcional de revisión, y se verifica después de un resize en el flujo MCP real.
- `document_preflight` detecta contenido activo, recursos externos, `foreignObject` y documentos inválidos sin mutarlos; se ejecuta antes de los exports en la integración MCP.
- `document_pages` implementa el adapter de páginas explícitas de Inkscape 1.4 (`sodipodi:namedview` + `inkscape:page`) y permite listar, añadir, actualizar, eliminar y reordenar IDs estables bajo revisión optimista. La integración MCP cubre alta y lectura antes de exportar.
- `document_settings` lee y actualiza `pagecolor`, `inkscape:pageopacity`, `inkscape:deskcolor`, `bordercolor` y `borderopacity` con valores por defecto observados en las plantillas de Inkscape 1.4.4; el flujo MCP verifica el round-trip tipado.
- `document_create` acepta dimensiones custom o presets versionados `a3`, `a4` y `letter` en retrato/paisaje; la prueba MCP crea A4 mediante `a4-portrait`.
- La creacion admite ahora una lista inicial de paginas explicitas de Inkscape; la integracion MCP crea `page_front`, agrega `page_back` y exporta el documento resultante.
- `document_inspect` incluye dimensiones, unidades de viewport, `viewBox`, paginas explicitas y revision SHA-256 en una respuesta de solo lectura.
- `document_resize` acepta los nueve anchors tipados para `page_only`; el plan geometrico conserva el centrado historico de contain/cover y calcula matrices de transformacion ancladas.
- `document_resize` aplica `scale_content_contain` y `scale_content_cover` mediante un grupo SVG transformado, preserva `defs`/metadata/namedview fuera del grupo y emite `CONTENT_MAY_BE_CROPPED` para cover. Un documento sin contenido renderizable recibe `NO_RENDERABLE_CONTENT` en vez de fallar.
- `scale_content_stretch` es un modo explicitamente solicitado; usa escala X/Y independiente y devuelve `NON_UNIFORM_CONTENT_SCALE` para que el cliente no confunda deformacion con contain/cover.
- `BoundsDescriptor` separa `geometric`, `visual` y `approximate`: el DOM
  actual nunca afirma cálculo geométrico exacto sin un motor SVG/CSS probado;
  `--query-all` se expone como observación visual de fidelidad `partial`.
  `elements_query(includeBounds=true)` devuelve ahora `kind`, `fidelity`,
  `source` y limitaciones junto a cada caja nativa.
- El corpus de fidelity cubre coordenadas negativas, transforms anidados,
  stroke, markers, filters, cascade/especificidad CSS, `!important`,
  `currentColor`, variables, porcentajes, `objectBoundingBox` y
  `non-scaling-stroke`; estas features se declaran approximate hasta disponer
  de un motor compatible validado.

## F03-WP02 (completo)

- Objetivo verificable: crear/inspeccionar documentos SVG mínimos con medidas
  inequívocas y, ante dimensiones ausentes, unitless o porcentuales, exponer
  la normalización y sus límites sin alterar el archivo durante la lectura.
- Prerrequisitos/puertas: F03-WP01 completo. `document_create`, presets,
  páginas e inspección base ya existían; este paquete completa T11.
- Interfaces: `inspectSvgSettings`, `parseViewportLength`,
  `document_inspect`, `document_resize` y `document_preflight` existentes.
- No-objetivos: resolver porcentajes contra una ventana/DOM host, alterar un
  documento durante `document_inspect`, o aplicar una normalización silenciosa
  antes de exportar.
- Resultado: dimensiones faltantes usan el viewport SVG 300 × 150 px con
  warnings estables; longitudes sin unidad se hacen CSS px explícitos; un
  `viewBox` ausente se deriva del viewport concreto a 96 dpi. Porcentajes se
  muestran con fallback marcado `percentage_fallback`, `ambiguousViewport` y
  warnings por eje; resize los rechaza hasta que se normalicen explícitamente.
  Preflight propaga estos warnings como recomendaciones sin falsificar error.

## F03-WP03 (completo)

- Objetivo verificable: ajustar página sin transformar objetos mediante fit a
  drawing/selección con márgenes por lado, crop/expand físicos y orientación.
- Prerrequisitos/puertas: F03-WP01/02 completos; los bounds nativos se
  mantienen declarados como `visual`/`partial` y no se confunden con geometría
  DOM exacta.
- Interfaces: `document_fit_page`, `document_page_adjust`,
  `fitPageToBoundsSvg`, `adjustPageMarginsSvg` y
  `changePageOrientationSvg`.
- No-objetivos: fit a paths sin ID, calcular CSS/stroke/filter geométricos o
  mover/escalar objetos para hacerlos caber.
- Resultado: fit usa `--query-all` sobre el bundle nativo inmutable; admite
  drawing completo o selección de IDs y devuelve bounds/fidelidad parcial más
  `FIT_USED_VISUAL_BOUNDS`. Crop y expand cambian tanto viewport como viewBox
  por cada margen físico, rechazan área no positiva y preservan el markup de
  objetos. El toggle de orientación intercambia dimensiones bajo un anchor y
  emite `PAGE_ORIENTATION_CHANGED`.

## F03-WP04 (completo)

- Objetivo verificable: prever un resize con tamaño, transformación y diff sin
  escribir, y comprobar consistencia del layout de páginas explícitas.
- Prerrequisitos/puertas: F03-WP01–03 completos; diff semántico de F02 y
  bounds visuales nativos de Inkscape están disponibles.
- Interfaces: `document_resize(dryRun=true)`, `document_page_validate`,
  `summarizeSvgDiff` y `validateSvgPageLayout`.
- No-objetivos: prometer que bounds de objetos son geométricos exactos,
  normalizar objetos sin ID ni convertir el diagnóstico de una página vacía en
  una mutación automática.
- Resultado: dry run comprueba la revisión, calcula SVG en memoria y retorna
  página/viewBox previstos, matriz de contenido cuando aplica, warnings y diff
  resumido; no crea backup ni modifica la revisión. La validación enumera
  solapamientos exactos entre rectángulos de página y, con bounds nativos
  marcados `partial`, páginas sin objeto visual y objetos fuera de toda página.

## F03-G02 (cerrada)

  geometría ni los transforms de los elementos del documento.
- Evidencia: el vector unitario compara todos los atributos de los hijos SVG
  antes/después de redimensionar A4 a 148 × 210 mm. El smoke MCP repite el
  contrato por stdio con un grupo transformado anidado, un `rect` con

  viewport y el `viewBox` del root.
- Resultado: `npm test -- --run tests/unit/documents.test.ts` pasó (35/35) y
  `npm run test:mcp` pasó el 2026-08-30 con negociación MCP fijada y legacy.
- Archivos: `tests/unit/documents.test.ts`, `scripts/test-mcp.mjs`,
  `PLAN_IMPLEMENTACION.md` y este informe.

  interprete estilos CSS complejos sigue cubierto por sus gates de fidelidad,
  no por este resize sin transformación.

## F03-G03 (cerrada)

- Objetivo: probar que contain, cover y fit calculan escala, bounds y anchor
  esperados en fixtures mecánicos.
- Evidencia: el modelo puro fija 800 × 600 → 1080 × 1080: contain usa escala
  1,35 y cover 1,8; `top_left` deja offset cero y `bottom_right` produce
  respectivamente `(0,270)` y `(-360,0)`. El vector de fit con bounds
  `(-10,20,100,50)` y 3 mm por lado produce `(-13,17,106,56)`.
- Smoke MCP: por stdio comprueba las matrices de contain/cover y el warning
  `CONTENT_MAY_BE_CROPPED`; además, el fit de un rectángulo nativo confirma
  bounds `(10,5,30,20)`, página 40 × 25 mm y viewBox `(5,3,40,25)`.
- Tolerancias: 12 decimales en cálculo DOM puro; 0,01 unidades en los valores
  observados por Inkscape, que se anuncian como visuales de fidelidad parcial.
- Resultado: `npm test -- --run tests/unit/geometry.test.ts`
  `tests/unit/documents.test.ts` pasó (40/40) y `npm run test:mcp` pasó el
  2026-08-30 con negociación MCP fijada y legacy.
- Archivos: `tests/unit/geometry.test.ts`, `tests/unit/documents.test.ts`,
  `scripts/test-mcp.mjs`, `PLAN_IMPLEMENTACION.md` y este informe.
- Riesgo residual: los bounds de `document_fit_page` proceden de Inkscape y
  permanecen `partial`; la exactitud CSS/pintura compleja se controla en G08.
