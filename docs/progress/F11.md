# F11 — Hardening, documentación, empaquetado y release Windows 1.0

## F11-WP01 (2026-08-27)

- El README ahora describe la instalación de Node/Inkscape en Windows, el
  diagnóstico `--doctor`, el inicio por stdio con workspace autorizado, una
  configuración MCP de ejemplo y el uso obligatorio de `expectedRevision`.
- El catálogo público está agrupado por operaciones reales de documento,
  diseño, recursos, imágenes, importación y exportación, en lugar de afirmar
  que sólo existían creación y resize.
- Evidencia: `npm run check` completó formato, lint, tipos y 179 pruebas (una
  omitida); `npm run pack:check` verificó la allowlist de publicación y `npm
run test:pack` instaló y ejecutó el paquete aislado correctamente.
- El smoke de paquete ahora comprueba además `--doctor --json` y un handshake
  MCP stdio con `inkscape_status` contra `dist/cli.js` dentro del `.tgz`
  instalado, no contra el árbol fuente.

## F11-WP02 (2026-08-27)

- `inkscape-mcp export` permite a PowerShell y automatizaciones locales ejecutar
  un preset sin un cliente de IA: inspecciona el SVG para tomar su revisión,
  solicita `document_export_preset_plan` y sólo después consume ese plan en
  `document_export_batch` atómico.
- Sus únicos argumentos propios son `--source`, `--preset`,
  `--output-directory`, `--workspace-index` y `--dry-run`; las rutas de
  documento y salida siguen siendo relativas y se validan antes de iniciar el
  hijo stdio. Los flags de configuración permitidos se reenvían sin ampliar el
  contrato público del servidor.
- `--dry-run` devuelve digest, vencimiento y outputs previstos sin crear el
  directorio destino. El smoke real crea un SVG temporal, verifica ese corte y
  luego comprueba el PNG publicado por `web-png`.
- Evidencia: `npm run check` completó 183 pruebas (una omitida) y `npm run
test:cli` superó la exportación real con Inkscape.
