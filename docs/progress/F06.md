# F06 - Motor de elementos y diseno basico

## F06-WP01 (en curso)

- Objetivo verificable: ampliar `elements_query` con un subconjunto de selector
  CSS seguro, determinista y acotado, preservando la distinción entre un ID
  ausente y una selección válida sin coincidencias.
- Prerrequisitos/puertas: F02 sanitiza el SVG antes del DOM; el motor de
  cascada CSS expone sólo su subconjunto soportado y declara limitaciones. Las
  cajas se consultan de forma opt-in desde Inkscape sobre un
  bundle nativo inmutable y requieren revisión esperada.
- Interfaces disponibles (no inventar otras): `querySvgElements`,
  `elements_query`, schemas Zod y `sanitizeSvg`.
- Archivos/artefactos esperados: dominio de elementos, contrato MCP, pruebas
  unitarias focalizadas y esta evidencia.
- Tareas condicionales permitidas (`[-]`/`[w]`): ninguna.
- No-objetivos: selectores con combinadores, atributos, pseudoclases o listas;
  ejecución de CSS o consultas arbitrarias a Inkscape.
- Comandos exactos: `npm test -- --run tests/unit/documents.test.ts`,
  `npm run check`.
- Assertions/tolerancias: un selector admite como máximo un tipo, un ID y ocho
  clases; se rechazan profundidad mayor de 128 y más de 10.000 matches antes
  de paginar.
- Resultado: `F06-T01` y `F06-T02` completadas. `elements_query` conserva
  filtros por ID/tipo/layer y añade `selector` como compuesto único
  (`rect#id.claseA.claseB`); el ID dentro del selector participa en
  `missingIds`. Se rechazan espacios, combinadores, atributos, pseudoclases,
  tipos no allowlisted, más de ocho clases, más de 10.000 coincidencias y
  nesting de más de 128 elementos. La entrada MCP de esta tool es ahora
  estricta. `F06-T04` está completada: `includeBounds=true` exige
  `expectedRevision`, crea un `NativeInputBundle` y una segunda copia privada
  con IDs remapeados a un alfabeto seguro para `--query-all`. El mapa reversible
  sólo devuelve bounds a IDs fuente únicos; los duplicados se omiten para no
  atribuir una caja incorrecta. Los IDs no públicos se mantienen sólo como
  correlación interna y jamás aparecen en la respuesta MCP. El estilo calculado
  cubre presentación, CSS compuesto seguro, inline, herencia y `!important`;
  CSS fuera del subconjunto se informa como fidelidad parcial. La prueba MCP
  real cubre IDs con coma, punto y coma, espacio y Unicode, y el schema público
  rechaza controles.
- Evidencia: `npm run check` (132 pruebas activas), pruebas unitarias de
  normalización/rewrite de IDs y `npm run test:mcp` (stdio moderno y legacy,
  incluida la consulta nativa real con delimitadores y Unicode) el 2026-08-26.

## F06-WP02 (inicio)

- `elements_create` crea batches de 1 a 100 rects (incluidos rounded),
  circles, ellipses, lines, polylines y polygons mediante schemas tipados.
- Cada forma valida finitud, rangos, color hexadecimal seguro y IDs sin
  espacios/controles; las colisiones se rechazan y las mutaciones usan revision
  esperada, backup y commit atomico.
- La integracion MCP crea un rectangulo rojo y lo exporta mediante
  `area=drawing` con Inkscape real.
- El mismo schema crea texto escapado como contenido de nodo, no markup, con
  tipografia inicial `fontFamily`, `fontSize`, `fontWeight` y `textAnchor`.
  El texto admite hasta 100 `tspan` tipados con desplazamientos `dx`/`dy`.
- El batch admite `group` y `layer` con ID/label; los elementos posteriores
  pueden indicar `parentId` de un grupo/capa existente o creado antes, sin
  reparenting libre ni referencias hacia adelante.
- `elements_create` acepta paths SVG mediante un parser cerrado de `d` para
  M/L/H/V/C/S/Q/T/A/Z, incluidos límites, finitud y flags/radios de arco.
- También genera `regular_polygon`, `star` y `spiral` como SVG estándar desde
  parámetros numéricos.
- `elements_delete` borra IDs explicitamente seleccionados y adopta una politica
  conservadora: rechaza el batch si una referencia `href` de un elemento que
  queda vivo se volveria rota.
- `elements_transform` acepta solo transformaciones numericas tipadas
  translate/scale/rotate/skew/flip/matrix y las anexa al transform existente;
  no acepta cadenas SVG arbitrarias ni matrices singulares.
- `elements_query` devuelve resúmenes en orden documental por IDs, tipo o capa,
  con `limit`/`offset` acotados y `missingIds`; puede añadir estilos calculados
  de su subconjunto CSS y bounds visuales consultados desde Inkscape mediante
  un bundle inmutable con IDs remapeados.
- `elements_update` aplica batches con revisión esperada para parches tipados
  de geometría por tipo, estilo básico, contenido de `<text>` y label de capas.
  Rechaza XML, atributos/transform strings arbitrarios y parches incompatibles
  con el tipo real del elemento.
- `elements_arrange` ofrece front/back y un paso raise/lower solo entre
  hermanos. Aún no implementa índices, referencias relativas, alineación ni
  distribución, por lo que `F06-T21` sigue abierta.
- `elements_group` agrupa hermanos o desagrupa un `<g>` no-layer conservando
  el orden de los hijos y rechazando `href` externos al grupo. Reparenting y
  group/ungroup de capas continúan fuera de este corte; `F06-T20` sigue abierta.
- `elements_query(includeComputedStyle=true)` resuelve presentación, CSS
  compuesto seguro, inline, herencia y `!important`; expone
  `exact-supported` sólo si no detecta variables, at-rules ni selectores
  avanzados. Esos casos devuelven fidelidad `partial` y limitaciones
  explícitas. La prueba MCP real confirma el `fill` calculado de un elemento
  creado.
- Pendiente: CSS universal, edición avanzada de paths, arrange, reparenting y
  transacciones de operaciones heterogeneas.

## F06-WP03 (completado)

- `elements_create` incorpora imágenes PNG/JPEG/GIF/WebP solamente desde un
  `assetPath` local y canónico. `embedding=link` conserva un URI relativo;
  `embedding=embed` produce un Base64 `data:image` raster. URLs, SVGs y MIME
  declarados por el cliente no se aceptan.
- El sanitizador y `NativeInputBundle` reconocen exactamente el mismo
  subconjunto de data URIs raster; no intentan resolverlo como archivo local y
  mantienen prohibidos SVG/HTML/script embebidos y cualquier data URI en modo
  `strict`.
- IDs omitidos se generan secuencialmente (`shape_1`, `shape_2`, …) y nunca
  colisionan. La tool `document_normalize_ids` es la ruta explícita para
  normalizar IDs existentes y reescribir referencias locales compatibles;
  devuelve cada cambio y conserva los IDs únicos ya válidos.
- Evidencia: `npm run check` (136 pruebas activas) y `npm run test:mcp`
  aprobados el 2026-08-26; el recorrido MCP crea imágenes linked/embed y
  comprueba normalización de href, `url()` y CSS.

## F06-WP04 (en curso)

- `elements_delete` ahora inspecciona cada ID del subárbol que se eliminaría y
  rechaza `href`, `xlink:href`, listas ARIA y fragmentos `url(#…)` presentes
  tanto en atributos como en CSS vivo. Así no publica filtros, clips, masks o
  definiciones rotas; una prueba MCP negativa confirma que el commit no ocurre.
- `elements_duplicate` diferencia `mode=copy` (copia independiente de un
  elemento simple) de `mode=use` (clone SVG mediante `<use href="#origen">`).
  Ambos requieren revisión esperada, IDs públicos nuevos y commit atómico.
- Una copia de subárbol con IDs descendientes se rechaza de forma explícita:
  duplicarla sin remapear sus referencias internas sería incorrecto. El
  remapeo profundo queda para el bloque de paths/defs avanzado.
- Pruebas unitarias cubren copy, clone y rechazo del subárbol; la integración
  MCP crea ambos modos dentro de un grupo y completa después las operaciones
  reales de inspección/exportación. `npm run check` (136 activas) y
  `npm run test:mcp` aprobados el 2026-08-26.
