## F02-WP02 (completo)

- Las exportaciones PNG, PDF y SVG ya congelan el SVG de origen en el staging y
  validan su hash antes y después de la copia; Inkscape no recibe la ruta viva
  del workspace. La copia de dependencias locales y la reescritura de URI
  siguen pendientes en `F02-T24`.
- Antes de congelar la copia, el pipeline rechaza XML/SVG que la política
  `preserve-local` tendría que limpiar; contenido activo y referencias remotas
  no se entregan al proceso nativo.
- Las mutaciones de resize aplican la misma regla antes de volver a parsear el
  XML: un SVG que requiera limpieza se rechaza sin modificar el documento.

- `ScratchManager` crea dirs únicos de job/probe/staging, garantiza limpieza `finally` y recolecta solo dirs propios obsoletos durante arranque.
- `sha256File` calcula revisiones por stream; una mutación interna porta `MutationDocumentRef` y el overwrite exige la revisión actual del destino.
- Locks por rutas canónicas se adquieren en orden léxico, evitando deadlocks entre source y output.
- `AtomicFileStore` escribe y sincroniza un temporal en el mismo directorio, crea backup único al reemplazar y después hace rename; ADR-005 declara los límites crash/Windows de esta operación.
- Las pruebas cubren revisión obsoleta, overwrite sin revisión, backup y dos writers concurrentes.
- `SnapshotStore` guarda documentos y metadata interna por IDs opacos con
  owner, TTL persistente y retención de 100 snapshots por workspace. Al
  restaurar revalida el hash del snapshot y la revisión actual del destino,
  delegando el reemplazo y backup al `AtomicFileStore`.
- `document_snapshot` exige `expectedRevision`, y `document_restore` exige la
  revisión actual, el ID opaco y el mismo workspace owner. La prueba MCP crea,
  restaura y vuelve a redimensionar un A4; no se aceptan snapshots sin revisión
  ni de otro workspace. `npm run check` pasó con 65 pruebas y una omitida, y
  `npm run test:mcp` pasó en stdio moderno y legacy el 2026-08-25.

## F02-WP03 (completo)

- Objetivo verificable: aplicar el ceiling de confianza a los bundles nativos y
  ampliar la sanitización para recursos y CSS externos sin dañar las referencias
  locales permitidas.
- Prerrequisitos/puertas: F02-WP02 cerrado; `sanitizeSvg` y
  `createNativeInputBundle` son las únicas interfaces que se ampliarán.
- Interfaces disponibles (no inventar otras): `SanitizeMode`, `sanitizeSvg`,
  `NativeInputBundle` y la configuración de arranque ya validada.
- Archivos/artefactos esperados: sanitizador, bundle nativo, pruebas de corpus
  y este informe.
- Tareas condicionales permitidas (`[-]`/`[w]`): ninguna.
- No-objetivos: aceptar `trusted` desde una tool, interpretar CSS completo o
  implementar todavía el remapeo integral de IDs/diff semántico.
- Comandos exactos: `npm test -- --run tests/unit/safe-svg.test.ts`
  `tests/unit/storage.test.ts`, `npm run check`.
- Assertions/tolerancias: `strict` permite solo refs fragmentarias; el ceiling
  `strict` convierte la sanitización nativa por defecto a strict y ningún
  bundle nativo recibe contenido que haya requerido limpieza.
- Resultado: T18–T21 completadas. `sanitizeSvg` elimina scripts, eventos,
  `foreignObject` estricto, refs externas y URLs externas en atributos/CSS;
  `createNativeInputBundle` usa el ceiling configurado y nunca eleva a
  `trusted`. `normalizeSvgIds` conserva la primera definición de duplicados,
  normaliza IDs inválidos/opcionalmente faltantes y actualiza `href`, ARIA,
  `url(#...)` en fill/clip/mask/filter/marker y selectores CSS literales o
  escapados conocidos. `summarizeSvgDiff` ofrece conteos e IDs, no markup.

- ADR-009 compara `fast-xml-parser` y `@xmldom/xmldom`; se eligió este último por DOM/serialización y fidelidad de namespaces, defs y comentarios bajo MIT.
- El parser rechaza DTD, entidades, CDATA, payloads grandes y exceso de elementos antes de exponer un DOM.
- La sanitización ya quita scripts/event handlers y controla `foreignObject`/referencias según el modo. Resta conectar el ceiling de confianza configurado y la normalización semántica de IDs.
